# ST_Alarm

---

# Purpose

Represents a single alarm generated by the AquaFeed Platform.

Every active or historical alarm shall follow this structure.

---

# Structure

```iecst
TYPE ST_Alarm :
STRUCT

    AlarmId             : UINT;

    AlarmCode           : UINT;

    AlarmLevel          : E_AlarmLevel;

    AlarmSource         : E_AlarmSource;

    Active              : BOOL;

    Acknowledged        : BOOL;

    Cleared             : BOOL;

    ActivatedTime       : DT;

    ClearedTime         : DT;

    UserId              : UINT;

    LineId              : USINT;

    DeviceId            : UINT;

END_STRUCT
END_TYPE
```

# Description

## AlarmId

Unique alarm record identifier.

---

## AlarmCode

Unique alarm definition code.

The Desktop Application shall translate this code into:

- Alarm title
- Alarm description
- Language-specific text
- Recommended action

This allows multilingual support without increasing PLC memory usage.

---

## AlarmLevel

Alarm severity.

Examples

- Information
- Warning
- Error
- Critical

---

## AlarmSource

Origin of the alarm.

Examples

- PLC
- Line
- Blower
- Selector
- Dosing
- Communication
- Safety

---

## Active

Alarm is currently active.

---

## Acknowledged

Operator has acknowledged the alarm.

---

## Cleared

Alarm condition no longer exists.

---

## ActivatedTime

Time when the alarm became active.

---

## ClearedTime

Time when the alarm was cleared.

---

## UserId

Operator acknowledging the alarm.

---

## LineId

Associated feeding line.

0 = System Alarm

---

## DeviceId

Related device identifier.

---

```text
Normal
   │
   ▼
Active
   │
   ▼
Acknowledged
   │
   ▼
Cleared
   │
   ▼
Archived
```

---

# Rules

Every alarm shall have a unique AlarmCode.

Critical alarms may stop machine operation.

Information alarms shall never stop production.

An alarm cannot be acknowledged before it becomes active.

A cleared alarm remains available in history.

The PLC stores only AlarmCode.

Alarm descriptions are generated by the Desktop Application using the Alarm Dictionary.

---

# Lifetime

Active alarms remain in PLC memory.

Alarm history is permanently stored in the database.
